Exception Handling — Square Root with Custom Exception

① Aim

To write a Python program that computes the square root of a number entered by the user, and to handle invalid input (non-numeric values) and negative numbers using Python's exception-handling mechanism, including a custom exception class derived from Exception.

② Objective

The student will learn how to define and raise a custom exception class, use try/except/raise, and validate user input defensively before performing a mathematical operation.

③ Problem Statement

Create a program to find the square root of a number. The program must raise an exception when the user enters a negative number, and must also handle the case where the user enters invalid (non-numeric) input. Use the Exception class.

④ Software / Tools Required

  • Python 3.x (interpreter)
  • Any code editor — VS Code, PyCharm, IDLE, or Notepad
  • Command Prompt / Terminal to run the script

⑤ Prerequisites

  • Basic Python syntax (variables, functions, input(), print())
  • Concept of try-except-raise
  • Basic class inheritance (a custom exception is a class that inherits from Exception)

⑥ Algorithm

  1. Define a custom exception class NegativeNumberError that inherits from Exception.
  2. Prompt the user to enter a number.
  3. Attempt to convert the input to a float.
  4. If the conversion fails, Python automatically raises a ValueError — catch it and display a friendly message.
  5. If the conversion succeeds but the number is negative, manually raise NegativeNumberError.
  6. Otherwise, compute the square root using math.sqrt() and display the result.

⑧ Complete Source Code

square_root.py
import math

class NegativeNumberError(Exception):
    """Custom exception raised when a negative number is given for square root."""
    def __init__(self, message="Cannot compute square root of a negative number."):
        self.message = message
        super().__init__(self.message)


def compute_square_root():
    try:
        user_input = input("Enter a number to find its square root: ")
        number = float(user_input)          # may raise ValueError

        if number < 0:
            raise NegativeNumberError()

        result = math.sqrt(number)
        print(f"Square root of {number} is {result}")

    except NegativeNumberError as e:
        print(f"Error: {e}")

    except ValueError:
        print("Error: Invalid input. Please enter a valid numeric value.")

    finally:
        print("Program execution completed.")


if __name__ == "__main__":
    compute_square_root()

⑨ Code Explanation

Class Explanation

NegativeNumberError is a user-defined exception class that inherits from Python's built-in Exception class. It overrides __init__ to store a custom message.

Function Explanation

compute_square_root() wraps all the logic inside a try block so any error during conversion or validation is caught cleanly.

Important Lines

  • float(user_input) — automatically raises a built-in ValueError if the text cannot be converted to a number (e.g., "abc").
  • raise NegativeNumberError() — manually triggers our custom exception when the number is valid but negative.
  • The finally block always executes, regardless of whether an exception occurred — useful for cleanup messages.

⑬ Viva Questions

Q1. What is an exception in Python?
Answer: An exception is an event that disrupts the normal flow of a program's execution, typically caused by an error at runtime (e.g., invalid input, division by zero).
Q2. Why do we create a custom exception class instead of just using ValueError?
Answer: A custom exception gives a more specific, descriptive name and message tailored to the exact business rule being violated (here, "negative number not allowed"), improving code readability and error handling precision.
Q3. What is the role of the raise keyword?
Answer: raise manually triggers an exception at a specific point in the code, interrupting normal execution and transferring control to the nearest matching except block.
Q4. What is the difference between except and finally?
Answer: except runs only when a matching exception occurs; finally always runs, whether or not an exception occurred, and is typically used for cleanup.
Q5. Why must a custom exception class inherit from Exception?
Answer: Inheriting from Exception ensures the class integrates properly with Python's exception-handling machinery (can be raised, caught, and displays correctly with a traceback).
Q6. What would happen if the negative-number check were removed?
Answer: math.sqrt() would raise its own built-in ValueError ("math domain error") for negative inputs, which is less descriptive than our custom exception.
Q7. What does super().__init__(self.message) do?
Answer: It calls the parent Exception class's constructor, passing the custom message so it is stored and displayed correctly when the exception is printed.

class Product:
    """Represents a single product with a name, code, and price."""

    def __init__(self, name, product_code, price):
        self.name = name
        self.product_code = product_code
        self.price = price

    def display_details(self):
        print(f"Product Name  : {self.name}")
        print(f"Product Code  : {self.product_code}")
        print(f"Product Price : Rs. {self.price:.2f}")

    def apply_discount(self, percent):
        """Reduces price by the given percentage and returns the new price."""
        discount_amount = (self.price * percent) / 100
        self.price -= discount_amount
        return self.price

    def __str__(self):
        return f"{self.name} ({self.product_code}) - Rs.{self.price:.2f}"

banking_app.py
class InsufficientFundsError(Exception):
    """Raised when a withdrawal or transfer exceeds the available balance."""
    def __init__(self, message="Insufficient balance for this operation."):
        super().__init__(message)


class Account:
    """Represents a simple bank account."""

    def __init__(self, account_holder, initial_balance=0):
        self.account_holder = account_holder
        self.__balance = initial_balance   # private attribute (encapsulation)

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit amount must be positive.")
        self.__balance += amount
        print(f"[{self.account_holder}] Deposited Rs.{amount:.2f}. "
              f"New balance: Rs.{self.__balance:.2f}")

    def withdraw(self, amount):
        if amount <= 0:
            raise ValueError("Withdrawal amount must be positive.")
        if amount > self.__balance:
            raise InsufficientFundsError(
                f"{self.account_holder} has insufficient balance "
                f"(available: Rs.{self.__balance:.2f})")
        self.__balance -= amount
        print(f"[{self.account_holder}] Withdrew Rs.{amount:.2f}. "
              f"New balance: Rs.{self.__balance:.2f}")

    def transfer(self, other_account, amount):
        """Transfers 'amount' from this account to 'other_account'."""
        self.withdraw(amount)          # will raise if insufficient funds
        other_account.deposit(amount)
        print(f"Transferred Rs.{amount:.2f} from "
              f"{self.account_holder} to {other_account.account_holder}")

    def balance(self):
        return self.__balance


if __name__ == "__main__":
    # Create two account objects
    acc1 = Account("Riya", 5000)
    acc2 = Account("Aman", 2000)

    print("===== Initial Balances =====")
    print(f"Riya: Rs.{acc1.balance():.2f}  |  Aman: Rs.{acc2.balance():.2f}")

    print("\n===== Deposit Test =====")
    acc1.deposit(1500)

    print("\n===== Withdraw Test =====")
    acc2.withdraw(500)

    print("\n===== Transfer Test =====")
    acc1.transfer(acc2, 2000)

    print("\n===== Exception Test: Over-withdrawal =====")
    try:
        acc2.withdraw(100000)
    except InsufficientFundsError as e:
        print(f"Error: {e}")

    print("\n===== Final Balances =====")
    print(f"Riya: Rs.{acc1.balance():.2f}  |  Aman: Rs.{acc2.balance():.2f}")

⑦ Code Explanation

Class Explanation

Account encapsulates the balance as a private attribute (__balance) so it cannot be modified directly from outside the class — it can only change through deposit(), withdraw(), or transfer().

Method Explanation

  • deposit(amount) — validates the amount is positive, then increases the balance.
  • withdraw(amount) — validates the amount and raises InsufficientFundsError if funds are insufficient.
  • transfer(other_account, amount) — demonstrates object-to-object interaction: it calls withdraw() on itself and deposit() on the other Account object.
  • balance() — a getter method that safely exposes the private balance.

Abstract Class and Inheritance — Shape, Triangle, Rectangle

① Aim

To create an abstract base class Shape storing two double values, derive Triangle and Rectangle classes from it, and compute/display the area of the shape entered interactively by the user.

② Objective

The student will learn abstract classes (via Python's abc module), method overriding, polymorphism (overloading display_area() in each subclass), and interactive user input handling.

③ Problem Statement

Create an abstract base class called Shape to store two double type values used to compute the area of figures. Derive Triangle and Rectangle from Shape. Add get_data() to initialize base class variables and display_area() to compute and display area. Override/redefine display_area() in each derived class. Accept dimensions interactively and display the area: Rectangle Area = X*Y; Triangle Area = (X*Y)/2.

④ Software / Tools Required

  • Python 3.x
  • Code editor
  • Terminal

⑤ Prerequisites

  • Inheritance and method overriding
  • Abstract base classes (abc.ABC, @abstractmethod)
  • Polymorphism

⑥ Complete Source Code

shapes.py
from abc import ABC, abstractmethod


class Shape(ABC):
    """Abstract base class storing two double values (x, y)."""

    def __init__(self):
        self.x = 0.0
        self.y = 0.0

    def get_data(self):
        """Initializes base class variables from user input."""
        self.x = float(input("Enter first value (X): "))
        self.y = float(input("Enter second value (Y): "))

    @abstractmethod
    def display_area(self):
        """To be overridden by every derived class."""
        pass


class Rectangle(Shape):
    def display_area(self):
        area = self.x * self.y
        print(f"Area of Rectangle = {self.x} * {self.y} = {area}")


class Triangle(Shape):
    def display_area(self):
        area = (self.x * self.y) / 2
        print(f"Area of Triangle = ({self.x} * {self.y}) / 2 = {area}")


def main():
    print("Choose a shape:")
    print("1. Rectangle")
    print("2. Triangle")
    choice = input("Enter choice (1/2): ")

    if choice == "1":
        shape = Rectangle()
        print("\n-- Enter length (X) and breadth (Y) --")
    elif choice == "2":
        shape = Triangle()
        print("\n-- Enter base (X) and height (Y) --")
    else:
        print("Invalid choice.")
        return

    shape.get_data()
    shape.display_area()


if __name__ == "__main__":
    main()

⑦ Code Explanation

Class Explanation

Shape is declared abstract by inheriting from ABC and marking display_area() with @abstractmethod — this means Shape itself cannot be instantiated directly; only its concrete subclasses (Rectangle, Triangle) can be.

Method Explanation

  • get_data() — defined once in the base class and inherited by both subclasses (no need to repeat it).
  • display_area() — declared abstract in Shape, then overridden (redefined) separately in Rectangle and Triangle with different formulas — this is runtime polymorphism.

⑪ Viva Questions

Q1. What is an abstract class?
Answer: A class that cannot be instantiated on its own and typically contains one or more abstract methods that must be implemented by any concrete subclass.
Q2. What module provides abstract class support in Python?
Answer: The abc module, via the ABC base class and the @abstractmethod decorator.
Q3. What is method overriding, and where does it occur here?
Answer: Method overriding is redefining a method in a subclass that already exists (as abstract) in the parent class. Here, display_area() is overridden separately in Rectangle and Triangle.
Q4. Why is get_data() not overridden in the subclasses?
Answer: Because the logic to read two numeric values is identical for both shapes, so it is defined once in the base class and reused (inherited) — this avoids code duplication.
Q5. What would happen if we removed @abstractmethod from display_area()?
Answer: Shape would become a concrete class, and Python would allow direct instantiation of Shape(), even without a meaningful display_area() implementation — defeating the design intent.

books_db.py
import sqlite3


def create_table(cursor):
    cursor.execute("""
        CREATE TABLE IF NOT EXISTS books_master (
            book_id INTEGER PRIMARY KEY,
            book_name TEXT NOT NULL,
            author_name TEXT NOT NULL
        )
    """)


def insert_book(cursor, connection):
    book_id = input("Enter Book ID: ")
    book_name = input("Enter Book Name: ")
    author_name = input("Enter Author Name: ")

    cursor.execute(
        "INSERT INTO books_master (book_id, book_name, author_name) VALUES (?, ?, ?)",
        (book_id, book_name, author_name)
    )
    connection.commit()
    print("\nBook record inserted successfully!\n")


def display_all_books(cursor):
    cursor.execute("SELECT book_id, book_name, author_name FROM books_master")
    rows = cursor.fetchall()

    print("\n{:<10} {:<30} {:<25}".format("Book ID", "Book Name", "Author Name"))
    print("-" * 65)
    for row in rows:
        print("{:<10} {:<30} {:<25}".format(row[0], row[1], row[2]))


def main():
    connection = sqlite3.connect("library.db")
    cursor = connection.cursor()

    create_table(cursor)

    while True:
        print("\n===== BOOKS MASTER MENU =====")
        print("1. Insert a new book")
        print("2. Display all books")
        print("3. Exit")
        choice = input("Enter your choice: ")

        if choice == "1":
            insert_book(cursor, connection)
        elif choice == "2":
            display_all_books(cursor)
        elif choice == "3":
            print("Exiting... Goodbye!")
            break
        else:
            print("Invalid choice, try again.")

    connection.close()


if __name__ == "__main__":
    main()

⑦ Code Explanation

  • sqlite3.connect("library.db") — opens (or creates) a database file named library.db in the current folder.
  • CREATE TABLE IF NOT EXISTS — ensures the table is created only once, even if the script runs multiple times.
  • The ? placeholders in the INSERT statement are parameterized queries — they prevent SQL injection, unlike directly formatting user input into the SQL string.
  • connection.commit() — permanently saves the inserted data to the database file.
  • cursor.fetchall() — retrieves every row returned by the last executed SELECT query as a list of tuples.

① Aim

Write a simple client-server socket program in which a client connects to a given host and port, and reads any available data from the socket.

④ Software / Tools Required

⑥ Architecture Diagram

      │     SERVER      │                     │      CLIENT      │
      │ (server.py)      │                     │ (client.py)      │

      │  listen()        │◀────connection────▶│                  │

⑦ Complete Source Code

server.py
import socket

HOST = "127.0.0.1"   # localhost
PORT = 65432

def start_server():
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as server_socket:
        server_socket.bind((HOST, PORT))
        server_socket.listen()
        print(f"Server listening on {HOST}:{PORT} ...")

        conn, addr = server_socket.accept()
        with conn:
            print(f"Connected by client: {addr}")
            message = "Hello Client! This message is sent from the Server."
            conn.sendall(message.encode())
            print("Message sent to client.")

if __name__ == "__main__":
    start_server()
client.py
import socket

HOST = "127.0.0.1"   # server's IP address
PORT = 65432          # server's port number

def start_client():
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as client_socket:
        client_socket.connect((HOST, PORT))
        data = client_socket.recv(1024)   # read up to 1024 bytes
        print(f"Received from server: {data.decode()}")

if __name__ == "__main__":
    start_client()

⑧ Code Explanation

  • socket.AF_INET — specifies IPv4 addressing.
  • socket.SOCK_STREAM — specifies a TCP (connection-oriented, reliable) socket.
  • bind() — attaches the server socket to a specific host and port.
  • listen() — puts the server into listening mode, waiting for incoming connections.
  • accept() — blocks until a client connects, then returns a new connection object and the client's address.
  • connect() (client side) — establishes a connection to the server's host and port.
  • recv(1024) — reads up to 1024 bytes of data available on the socket.
  • The with ... as syntax ensures the socket is automatically closed when the block ends.

⑨ Execution Steps

  1. Create two files, server.py and client.py, in the same folder.
  2. Open Terminal Window 1, navigate to the folder, and run: python server.py. It will print "Server listening..." and wait.
  3. Open a second Terminal Window 2 (do not close the first), navigate to the same folder, and run: python client.py.
  4. Observe: the server terminal shows "Connected by client" and "Message sent to client"; the client terminal shows the received message.

Expected Output — Server Terminal

Server listening on 127.0.0.1:65432 ... Connected by client: ('127.0.0.1', 51762) Message sent to client.

Expected Output — Client Terminal

Received from server: Hello Client! This message is sent from the Server.

⑩ Common Errors and Solutions

OSError: [Errno 98] Address already in useA previous server instance is still using the portWait a few seconds, or change PORT to a different number

⑪ Viva Questions

Q1. What is a socket?
Answer: A socket is an endpoint for sending and receiving data across a network, identified by an IP address and a port number.
Q2. Why must the server start before the client?
Answer: The server must be actively listen()-ing on the port before a client can successfully connect() to it; otherwise the connection is refused.
Q3. What is the difference between SOCK_STREAM and SOCK_DGRAM?
Answer: SOCK_STREAM uses TCP — a reliable, connection-oriented protocol. SOCK_DGRAM uses UDP — a connectionless, faster but unreliable protocol.
Q4. What does accept() return?
Answer: A tuple containing a new socket object (used to communicate with that specific client) and the client's address (IP, port).
Q5. Why is data encoded/decoded (.encode() / .decode())?
Answer: Sockets transmit raw bytes, not Python strings, so text must be encoded to bytes before sending and decoded back to a string after receiving.

students/views.py
from django.shortcuts import render, redirect, get_object_or_404
from .models import Student

def student_list(request):
    students = Student.objects.all()
    return render(request, 'students/student_list.html', {'students': students})

def student_add(request):
    if request.method == 'POST':
        Student.objects.create(
            name=request.POST['name'],
            roll_number=request.POST['roll_number'],
            course=request.POST['course'],
            email=request.POST['email']
        )
        return redirect('student_list')
    return render(request, 'students/student_form.html', {'action': 'Add'})

def student_update(request, pk):
    student = get_object_or_404(Student, pk=pk)
    if request.method == 'POST':
        student.name = request.POST['name']
        student.roll_number = request.POST['roll_number']
        student.course = request.POST['course']
        student.email = request.POST['email']
        student.save()
        return redirect('student_list')
    return render(request, 'students/student_form.html', {'student': student, 'action': 'Update'})

def student_delete(request, pk):
    student = get_object_or_404(Student, pk=pk)
    if request.method == 'POST':
        student.delete()
        return redirect('student_list')
    return render(request, 'students/student_confirm_delete.html', {'student': student})

⑬ Viva Questions

Q1. What is Joomla?
Answer: Joomla is a free, open-source Content Management System (CMS) written in PHP, used to build and manage websites without writing extensive custom code.
Q2. What is the role of XAMPP in this practical?
Answer: XAMPP provides the local Apache web server, MySQL/MariaDB database, and PHP interpreter needed to run Joomla on a personal computer without a live web host.
Q3. What is the difference between a Joomla Article and a Category?
Answer: An Article is a single content item (here, one book's record); a Category is a grouping/classification that organizes multiple related Articles (here, a book genre).
Q4. Why must the "installation" folder be removed after setup?
Answer: For security — Joomla refuses to serve the site while the installer is present, preventing anyone from re-running the installation and overwriting the site.
Q5. How does a Joomla Module differ from an Article?
Answer: A Module is a small, reusable content block (e.g., Search box, Login form) displayed in a fixed position on the page layout, whereas an Article is the main page content itself.
Q6. How would member "borrow requests" typically be handled in this simple Joomla-based system?
Answer: Through the Contact component — members submit a request referencing the book title, which is emailed to the librarian; more advanced setups would use a dedicated library-management extension with a real request/approval workflow.
